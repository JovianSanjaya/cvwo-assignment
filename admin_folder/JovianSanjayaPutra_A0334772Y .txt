3. Technical Architecture
3.1 Frontend
The frontend is built using React and Typescript to ensure type safety and reduce
runtime errors. The technology stack was also chosen to fulfill the requirements of the
assignment. For state management, Redux is used to handle global application state that
needs to persist across pages including User session state and cached topic data to
reduce redundant API calls during navigation. Material UI (MUI) is used as the UI
library to provide a consistent design.
3.2 Backend
The backend is implemented using Go due to the requirement of the assignment. In this
project, I will be using go-chi as the HTTP router due to its lightweight design and
middleware support, which simplifies authentication and request handling.
The backend follows a layered architecture:
●​ handlers/: decoding JSON, validating inputs.
●​ models/: matching the database schema.

●​ db/: database connection and SQL queries.
3.3 Database
PostgreSQL is used as the relational database because it is also reliable at handling
massive amounts of information generated from the forums. In addition, I also have
prior experience working with PostgreSQL.
Schema Design:
●​ Users: id (PK), username (Unique), password_hash, created_at.
●​ Topics: id (PK), title, created_at.
●​ Posts: id (PK), title, content, topic_id (FK), user_id (FK), created_at.
●​ Comments: id (PK), content, post_id (FK), user_id (FK), created_at.
3.4 Authentication & Security
The application uses JSON Web Tokens (JWT) for user authentication. During
registration, user passwords are securely hashed using bcrypt before being stored in the
database to protect sensitive information. When a user logs in successfully, the backend
issues a JWT containing the user’s identity and an expiration time.
For actions such as creating, editing, or deleting posts, the system first checks whether
the user is logged in by verifying the JWT before processing the request. This ensures
that only authenticated users are allowed to modify content, while guest users are
limited to read-only access.
3.5 Docker and AWS
The application is containerized using Docker to ensure consistency between
development and deployment environments. Separate Dockerfiles are created for the
frontend and backend services which allows each of them to be built, configured, and
deployed independently. Docker Compose is used to orchestrate all services.
The application will be deployed on Amazon Web Services (AWS). The frontend and
backend services are hosted on an EC2 instance, while AWS RDS is used for the
production database. Using RDS provides managed backups and improved reliability.
