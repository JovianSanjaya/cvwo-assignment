3. Technical Architecture
3.1 Frontend
The frontend is built using React and TypeScript to ensure type safety and reduce
runtime errors. For state management, React Context API is used to handle global 
application state, primarily for managing the user session and authentication status 
through a custom AuthProvider. This ensures that user data and authentication tokens 
are accessible across all components. Material UI (MUI) is used as the UI library 
to provide a consistent and polished design, while Framer Motion is utilized for 
subtle animations.

3.2 Backend
The backend is implemented using Go. In this project, I am using go-chi as the 
HTTP router due to its lightweight design and excellent middleware support, which 
simplifies authentication and request handling.
The backend follows a layered architecture:
● handlers/: decoding JSON, validating inputs, and routing to logic.
● models/: matching the database schema and data structures.
● db/: database connection management and SQL query execution.

3.3 Database
PostgreSQL is used as the relational database due to its reliability and performance 
under load. 
Schema Design:
● Users: id (PK), username (Unique), password_hash, role, time_created.
● Topics: id (PK), title, user_id (FK), time_created.
● Posts: id (PK), title, content, topic_id (FK), user_id (FK), time_created.
● Comments: id (PK), content, post_id (FK), user_id (FK), time_created.
● Votes: id (PK), user_id (FK), post_id (FK), comment_id (FK), vote_type, time_created.

3.4 Authentication & Security
The application uses JSON Web Tokens (JWT) for user authentication. During registration, 
user passwords are securely hashed using bcrypt. When a user logs in successfully, 
the backend issues a JWT containing the user’s identity.
The application also integrates Google OAuth 2.0, allowing users to sign in seamlessly 
using their Google accounts. This is implemented using the @react-oauth/google 
library on the frontend and a dedicated authentication handler on the backend that 
validates Google tokens.

3.5 Docker and Deployment
The application is containerized using Docker to ensure consistency between 
environments. Separate Dockerfiles are created for the frontend and backend services, 
and Docker Compose is used to orchestrate them along with the PostgreSQL database.
The application is deployed using a hybrid approach: the frontend is hosted on 
Vercel for optimal delivery, while the backend service and PostgreSQL database 
are hosted on Amazon Web Services (AWS) using EC2 and RDS for reliability and scale.
